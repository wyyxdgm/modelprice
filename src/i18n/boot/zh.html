一句话结论：这个思路站得住 —— 但你原来的表述混了两件不同的事。加上下面的修正，它就变成一个严谨、可用的工具（就是本页）。

1. 「按 cost/task 排序 + 拖区间左边缘」本身并不产生赢家。 排序方向给不出结论；真正的操作是：固定门槛 T，取 score ≥ T 中 cost 最小的模型。 把 T 从最高分往下扫，赢家序列就是 (score, cost) 平面上的下包络（lower envelope / Pareto 前沿）。 可以证明映射 C(T) = min{cost : score ≥ T} 是单调不减的，所以「每一档都有赢家、门槛越高赢家越贵」必然成立 —— 你的直觉是对的。Arena 官方的 /pareto 视图画的就是这条曲线。 关键修正：赢家只在出现严格更便宜的模型时切换 —— 不是拖一步换一次 —— 所以前沿是一条阶梯，每一段平台就是「该模型统治的分数区间」。

2. 「最优性价比」至少有三种定义，答案各不相同：

  • 门槛制（Threshold）（= 你的想法，也是唯一在约束优化意义上正确的定义）：min cost s.t. score ≥ T。含义：「跨过这条线的模型里最便宜的」。
  • 每美元分数（Score per $）：max score/cost。含义：「每分最便宜」—— 但 Arena 分数带 ~1200 基线偏移，抬高了分子，所以这个口径几乎总选中最低廉的小模型。实用价值很小。
  • 超额分/$（Excess score per $）：max (score − baseline)/cost。去掉偏移后的边际价值，适合比较「多花钱、多买几分」的效率。

离采购决策最近的是边际价格：从当前档往上升一档，Δcost / Δscore = 每多买一分的美元数。档位表已经帮你算好。

3. 五个会翻转结论的坑（工具里每个都有开关）：

  1. 置信区间重叠。如果分数区间比 CI 还窄，区间内的排名就是噪声。例：HTML 榜上 Inkling 2 Small 只有 130 票（CI ±55）；Muse Spark Open ±41。 本工具提供「严格模式」：只接受「A 的 CI 下界 > B 的 CI 上界」的差距；统计上不可区分的相邻档合并为一档（保留更便宜的那个）。
  2. Preliminary（预评）/ 低票数。别给 <1000 票的模型加冕「性价比冠军」。
  3. Cost/Task (P50) 是任务混合的产物。同一个模型在不同榜（Overall / Frontend / Fullstack / HTML / React）上成本不同，因为任务长度和工具调用深度不同。 P50 还忽略长尾：agent 跑飞时 P95 可以是 P50 的 5–10×。而且它只覆盖 token 花费 —— 不含延迟、重试率、上下文窗口限制。
  4. 数据集截断。本次抓取中，frontend_os 与 overall_all 只覆盖了高分区（低分长尾没抓全）。 好消息：Pareto 前沿的高分端不受低分模型缺失的影响（更低分、更贵的模型永远进不了前沿）； 坏消息：「全场最低价」和「超额分/$」的基线会有偏差。用页面底部的粘贴框补齐缺口。
  5. 时点性。官方 API 返回 403，只能做页面快照；价格与排名每周都在变。CSV 导出的文件名带日期。

4. 你真正想问的问题，以及它在工具里的位置： 「在某张榜上、可接受的分数区间内，哪个模型性价比最好」→ 就是门槛制 + 分数区间滑块： 把 lo 设为你能接受的最低能力，hi 设为你不愿为其多付钱的天花板；卡片给出答案， 阶梯图告诉你「升一档要多花多少」—— 比单一冠军更有决策价值。

5. 一个反直觉但重要的提醒：Pareto 前沿上的模型互不支配；不存在「前沿上最好的那一个」。 「最好」取决于你的效用函数 —— 分数的边际效用衰减多快、预算多少。 所以正确的问题不是「哪个性价比最好」，而是「在我能接受的最低分数之上，每一美元能多买几分 —— 从哪一档起这个兑换率开始不值得」。 档位表的「边际成本 $/分」列就是这条兑换率曲线；找它的膝点（knee）。

6. 价格是时间的函数 —— 本版本把「小时」提升为一等变量。 榜面的 Price $/M 是抓取时刻的标价快照，而标价随时间变化。两类时间依赖已被核实：

  • 日内节律（峰谷价 peak/off-peak）。DeepSeek 峰时 = 工作日 01:00–04:00 与 06:00–10:00 UTC；其余时段（含整个周末）半价。 麻烦在于：榜面把两种口径混在一张表里 —— V4.1-Flash-20261017 标的是谷价 $0.15/$0.60，而 V4.1-Flash-20260910 和 V4-Pro 家族标的是峰价 $0.30/$1.20 和 $1.32/$3.96。跨行比较 = 拿一个模型的峰价比另一个模型的谷价。
  • 日历事件（促销到期）。11-11 快照里 GLM-5.3-Flash 榜面价 $0.05/$0.18 是首发促销价，已于 2026-09-09 结束（真实价 $0.15/$0.50，约 2.9×）—— 工具当时做了修正。11-20 快照已改列 $0.02/$0.07（低于促销后价，疑似新一轮促销），修正不再匹配，规则于 2026-11-22 下线。每条修正都按「榜面价精确匹配」生效；榜面更新后规则自动退出，而不是继续扭曲成本。

换算：Cost/Task = token 用量 × 单价；用量不随价格变，所以修正 = 按加权单价比例缩放： scale = [pin'·(1−w) + pout'·w] ÷ [pin·(1−w) + pout·w]，其中 w = 输出 token 占比，默认 8% （来自 Agent 榜：14 个模型反推的输入/输出比中位数 ≈ 11:1，范围 3.8–17.9×；滑块可调）。 DeepSeek 的峰谷价对输入输出同比例作用，所以对 w 不敏感；w 只对「输入输出涨幅不同」的修正有意义。

无损可逆：每个模型保留 cRaw（榜面原值）；所有情景都从它换算，关掉开关即精确还原 —— 不存在「改动漂离事实」。

结论确实随小时变化 —— 这正是意义所在：谷时 DeepSeek 老版半价，把 Hy3 和 MiMo-V2.5 挤出 Pareto 前沿（完全被支配）； T=1500 的赢家从 Hy3 $0.04 变为 DeepSeek-V4.1-Flash-20260910 $0.03；反过来峰时 20261017 从 $0.12 涨到 $0.24。 图③把它画成一周 168 小时的 C(T) 曲线：灰带 = 峰时窗口；折线跳变 = 冠军易主。

本节的三条边界：①分数是 2026-11-11 快照，不随时间变，所以时间轴反映的是价格的时间依赖，不是能力的（能力也随榜单更新漂移）； ②榜面成本用 P50 用量，不含缓存命中折扣（DeepSeek 缓存输入：峰 $0.006 / 谷 $0.003；Anthropic 缓存输入 $0.10–$1.00），所以真实 agent 账单可能远低于「用量 × 标价」； ③两条存疑规则（V4-Flash 是否也分峰谷；Mistral Medium 3.5 与 GPT-6 Sol 与第三方指数差 2×）默认关闭 —— 只用于敏感性分析。 规则表 PRICE_EVENTS 在源码里，随便改 —— 它就是「模型名 → 两个时段的单价」。 其中 gem_dec1 是未来事件：Gemini 4 Carbon/Argon 已公告 2026-12-01 从 $2/$10 涨到 $4/$20（缓存价 $0.10→$0.20）； 把计价日期拖进 12 月，你会看到它当天跌出 overall_all 前沿，被 GPT-6.1 Sol 取代。

7. 缓存命中率 —— 影响最大的单一变量（默认 95%）。 Arena 的 Cost/Task 按缓存未命中价（cache-miss）计算，而对前缀被反复重读的 agent 负载，这是系统性高估。 缓存折扣只作用于输入 token；输出永远全价： 有效输入价 = (1−h)·输入价·写入倍率 + h·输入价·缓存比，其中 h 是命中率。 两个容易漏掉的细节：①缓存读取价存的是相对输入价的比例，不是绝对值，所以峰谷价、促销到期、未来涨价都会自动带着缓存价一起变 （DeepSeek 峰 $0.006 → 谷自动 $0.003）； ②写入倍率：Anthropic（5 分钟档）与 OpenAI（30 分钟档）的缓存写入单独计费 = 输入价 1.25×，未命中的部分按写入价付， 所以同样 95% 命中率下 Claude 的折扣比 DeepSeek 薄；DeepSeek / Z.ai / 小米 / 腾讯 / Google（隐式缓存）/ xAI 不收写入费。 39 个模型用公布比例（DeepSeek 2%–3.3%、MiMo 0.8%–2%、Kimi 10%–20%、GLM 18.3%–20%、Hy3 25%、Grok 25%、 Anthropic 2.5%–10%、OpenAI 5%–10%、Gemini 5%、Mistral Large 4 10.3%）；其余 48 个无公布价 → 按行业惯例 10% 估算并在 UI 标「est.」， 或用「Flat 10%」统一压平做保守比较。 缓存价来源：DeepSeek 官方定价页；Anthropic / OpenAI / Google / xAI / Moonshot / Z.ai 定价页 （经 benchlm.ai、morphllm、sentra.app、maximem.ai、tech-insider、felloai、eesel、layer3labs、getnadir、imisofts、 munderdiffl.in、datastudios.org、aipricing.guru、glm-ai.chat、glm5.app、subconscious.dev、mem0.ai、llm-stats、orcarouter、 requesty.ai、codersera、saascity、alphasignal、truescho、flowtivity、deepseekai.guide 交叉核对）；完整对照表在 README。

缓存折扣带来的三个结论级变化：①水平：头部模型普遍省 59%–79%（Fable 5.2 $11.04→$4.10、Kimi $0.91→$0.375、MiMo-V2.6-Flash $0.05→$0.011）； ②前沿结构：overall_os 从 7 档变 8 档，三个 DeepSeek 变体挤进前沿； ③调度的价值被压缩：T=1600 的一周成本振幅从 1.67× 缩到 1.11× —— 缓存 95% 之后，躲峰时只能再多省 ~10%， 所以正确顺序是先修前缀缓存，再谈调度。 另外，「输出占比」滑块在缓存开启后从无关变量变成第二敏感参数：同样 95% 命中率下， DeepSeek-20261017 在 w=2% 省 86%、w=8%（默认）省 68%、w=15% 省 55%、w=25% 省 40%、w=40% 只省 25% —— 输出越长，缓存越救不了。反过来，如果某档冠军的输入输出价格同时翻倍（如 DeepSeek-20261017 在 T=1664）， 缓存压不住振幅 —— 仍是 2.00× —— 那一档的杠杆是调度。
