結論から言うと：このアプローチは成り立ちます —— ただしあなたの元の表現は2つの異なることを混ぜていました。以下の補正を加えれば、厳密で実用的なツール（このページ）になります。

1. 「cost/task でソート + 範囲の左端をドラッグ」だけでは勝者は出ません。 ソート方向は結論を生みません。本当の操作は：しきい値 T を固定し、score ≥ T の中で cost 最小のモデルを取ること。 T を最高スコアから下へスイープすると、勝者列は (score, cost) 平面の下包絡（lower envelope / パレートフロンティア）になります。 写像 C(T) = min{cost : score ≥ T} が単調非減少であることは証明でき、「すべてのTierに勝者がおり、しきい値が上がるほど勝者は高くなる」が必然的に従います —— あなたの直感は正しい。Arena 公式の /pareto 表示が描くのはまさにこの曲線です。 重要な補正：勝者は厳密により安いモデルが現れたときだけ切り替わる —— ドラッグ1 step ごとではない —— つまりフロンティアは階段であり、各平坦部は「そのモデルが支配するスコア範囲」です。

2. 「最コスパ」には少なくとも3つの定義があり、答えは異なります：

  • しきい値（Threshold）（= あなたのアイデアであり、制約付き最適化として正しい唯一の定義）：min cost s.t. score ≥ T。意味：「ハードルをクリアするモデルのうち最安」。
  • ドルあたりスコア（Score per $）：max score/cost。意味：「ポイントあたり最安」—— しかし Arena スコアは ~1200 のベースラインオフセットを持ち分子を水増しするため、この口径はほぼ常に最安の小型モデルを選びます。実用価値は小さい。
  • 超過スコア/$（Excess score per $）：max (score − baseline)/cost。オフセット除去後の限界価値。「多く払っていくら得か」の効率比較に有用。

購買意思決定に最も近いのは限界価格です：現在のTierから一つ上へ移動するとき、Δcost / Δscore = 追加ポイントあたりのドル。Tier テーブルが計算済みです。

3. 結論をひっくり返す5つの落とし穴（ツール内でそれぞれにスイッチあり）：

  1. 信頼区間の重なり。スコア範囲が CI より狭い場合、その範囲内の順位はノイズです。例：HTML ボードで Inkling 2 Small は 130 票のみ（CI ±55）；Muse Spark Open ±41。 本ツールには「厳密モード」があります：A の CI 下限 > B の CI 上限という差のみを受け入れ、統計的に区別できない隣接Tierは1つに統合します（安い方を保持）。
  2. Preliminary（暫定）/ 低票数。<1000 票のモデルに「コスパチャンピオン」の冠を与えないでください。
  3. Cost/Task (P50) はワークロード混合の産物。同一モデルでもボード（Overall / Frontend / Fullstack / HTML / React）によってコストが異なります。タスク長とツール呼び出し深度が異なるからです。 P50 は裾も無視します：agent が暴走したとき P95 は P50 の 5–10× になり得ます。しかもトークン費用のみをカバー —— レイテンシ、リトライ率、コンテキスト窓制限は含みません。
  4. データセットの切断。今回の取得では frontend_os と overall_all は高スコア帯のみカバー（低スコアの裾は取得しきれていません）。 良いニュース：パレートフロンティアの高スコア側は低スコアモデルの欠落に影響されません（より低スコアでより高いモデルはフロンティアに入れない）； 悪いニュース：「全体最安」と「超過スコア/$」の基準に偏りが出ます。ページ下部の貼付ボックスで穴を埋めてください。
  5. 時点性。公式 API は 403 を返すためページスナップショットしかできません；価格と順位は週ごとに変わります。CSV エクスポートのファイル名に日付が入ります。

4. あなたが本当に聞きたい質問と、ツール内での位置： 「あるボードで、許容できるスコア範囲内で、どのモデルが最コスパか」→ それはしきい値モード + スコア範囲スライダーです： lo をあなたの許容最低能力に、hi を追加支払いをしない天井に設定；カードが答えを出し、 階段チャートが「次Tierはいくら上か」を教えてくれます —— 単一チャンピオンより意思決定に有用です。

5. 反直感的だが重要なリマインダー：パレートフロンティア上のモデルは互いに非支配です。「フロンティア上のベスト」は存在しません。 「ベスト」はあなたの効用関数 —— スコアの限界効用がどれだけ速く減衰するか、予算はいくらか —— に依存します。 正しい質問は「どれが最コスパか」ではなく「私が受け入れられる最低スコアより上で、追加の1ドルは何ポイント買えるか —— そしてどのTierからその交換レートが割に合わなくなるか」です。 Tier テーブルの「限界コスト $/pt」列がまさにその交換レート曲線です；その膝点（knee）を見つけてください。

6. 価格は時間の関数 —— このバージョンでは「時刻」が一等変数です。 ボードの Price $/M は取得時点の定価スナップショットであり、定価は時間とともに変わります。検証済みの時間依存は2種類：

  • 日内リズム（ピーク/オフピーク）。DeepSeek のピーク = 平日 01:00–04:00 と 06:00–10:00 UTC；その他の時間帯（週末全体を含む）は半額。 厄介なのは：ボードが両方の基準を1つの表に混ぜていること —— V4.1-Flash-20261017 はオフピーク $0.15/$0.60 で掲載、一方 V4.1-Flash-20260910 と V4-Pro ファミリーはピーク $0.30/$1.20 と $1.32/$3.96 で掲載。行をまたいだ比較 = あるモデルのピークを別のモデルのオフピークと比べること。
  • カレンダーイベント（プロモ期限切れ）。11-11 スナップショットの GLM-5.3-Flash ボード価格 $0.05/$0.18 はローンチプロモで、2026-09-09 に終了済み（実際は $0.15/$0.50、約 2.9×）—— ツールは補正していました。11-20 スナップショットでは $0.02/$0.07（プロモ終了後価格より安い、新プロモの可能性）に更新され、補正が一致しなくなったためルールは 2026-11-22 に廃止。各補正は「榜面価格の完全一致」でのみ発動し、ボードが更新されればコストを歪めずにルールが外れます。

変換：Cost/Task = トークン使用量 × 単価；使用量は価格で変わらないため、補正 = 加重単価比によるスケーリング： scale = [pin'·(1−w) + pout'·w] ÷ [pin·(1−w) + pout·w]、ここで w = 出力トークン比率、デフォルト 8% （Agent ボードから：14 モデルの推定入力/出力比の中央値 ≈ 11:1、範囲 3.8–17.9×；スライダーで調整可）。 DeepSeek のピーク/オフピークは入出力に比例的に作用するため w に鈍感；w が効くのは入力と出力が異なる倍率で動く補正です。

損なしで可逆：全モデルが cRaw（ボードの生値）を保持；全シナリオはそこから導出され、スイッチを切れば正確に復元 —— 「編集が事実からずれる」ことはありません。

結論は本当に時刻で変わる —— それがポイントです：オフピークでは DeepSeek の旧バージョンが半額になり、Hy3 と MiMo-V2.5 をパレートフロンティアから追い出します（完全に支配される）； T=1500 の勝者は Hy3 $0.04 から DeepSeek-V4.1-Flash-20260910 $0.03 に変わる；逆にピークでは 20261017 が $0.12 から $0.24 に上がる。 チャート③はこれを 1 週間 168 時間の C(T) 曲線として描きます：灰色の帯 = ピーク時間帯；折線のジャンプ = トップ交代。

このセクションの3つの限界：①スコアは 2026-11-11 スナップショットで時間とともに変わらないため、時間軸が反映するのは能力ではなく価格の時間依存です（能力もボード更新とともにドリフトします）； ②ボードコストは P50 使用量でキャッシュヒット割引を含みません（DeepSeek キャッシュ入力：ピーク $0.006 / オフピーク $0.003；Anthropic キャッシュ入力 $0.10–$1.00）ので、実際の agent 請求は「使用量 × 定価」を大きく下回り得ます； ③2つの不確実なルール（V4-Flash もピーク/オフピークに分かれるか；Mistral Medium 3.5 と GPT-6 Sol が第三者インデックスと 2× 差）はデフォルトオフです —— 感度分析のみに使用。 ルール表 PRICE_EVENTS はソース内にあり、自由に編集できます —— 要は「モデル名 → 2時刻の単価」です。 そのうちの gem_dec1 は未来イベント：Gemini 4 Carbon/Argon は 2026-12-01 に $2/$10 から $4/$20 への値上げを発表済み（キャッシュ価格 $0.10→$0.20）； 価格設定日を12月にドラッグすれば、その日付で overall_all フロンティアから外れ、GPT-6.1 Sol に置き換わるのが見られます。

7. キャッシュヒット率 —— 最も影響の大きい単一変数（デフォルト 95%）。 Arena の Cost/Task はキャッシュミス価格で計算されるため、プレフィックスが絶えず再読み込みされる agent ワークロードにとっては体系的な過大評価です。 キャッシュ割引は入力トークンにのみ適用；出力は常に全額です： 実効入力価格 = (1−h)·入力価格·書き込み倍率 + h·入力価格·キャッシュ比、ここで h はヒット率。 見落とされやすい2つの詳細：①キャッシュ読取価格は絶対値ではなく入力価格に対する比率で保存されているため、ピーク/オフピーク・プロモ期限切れ・将来の値上げがキャッシュ価格を自動的に動かします （DeepSeek ピーク $0.006 → オフピークは自動で $0.003）； ②書き込み倍率：Anthropic（5分ティア）と OpenAI（30分ティア）はキャッシュ書き込みを入力価格の 1.25× で別課金し、ミス分は書き込み価格で支払うため、 同じ 95% ヒット率でも Claude の割引は DeepSeek より薄い；DeepSeek / Z.ai / Xiaomi / Tencent / Google（暗黙キャッシュ）/ xAI は書き込み料金なし。 39 モデルが公表比率を使用（DeepSeek 2%–3.3%、MiMo 0.8%–2%、Kimi 10%–20%、GLM 18.3%–20%、Hy3 25%、Grok 25%、 Anthropic 2.5%–10%、OpenAI 5%–10%、Gemini 5%、Mistral Large 4 10.3%）；残り 48 は公表価格なし → 業界標準の 10% で推定し UI に「est.」と表示、 または「Flat 10%」で一律に平らにして保守的な比較も可能。 キャッシュ価格の出典：DeepSeek 公式価格ページ；Anthropic / OpenAI / Google / xAI / Moonshot / Z.ai 価格ページ （benchlm.ai、morphllm、sentra.app、maximem.ai、tech-insider、felloai、eesel、layer3labs、getnadir、imisofts、 munderdiffl.in、datastudios.org、aipricing.guru、glm-ai.chat、glm5.app、subconscious.dev、mem0.ai、llm-stats、orcarouter、 requesty.ai、codersera、saascity、alphasignal、truescho、flowtivity、deepseekai.guide でクロスチェック）；完全な対照表は README に。

キャッシュ割引がもたらす3つの結論レベルの変化：①水準：上位モデルは概ね 59%–79% 節約（Fable 5.2 $11.04→$4.10、Kimi $0.91→$0.375、MiMo-V2.6-Flash $0.05→$0.011）； ②フロンティア構造：overall_os は 7 Tier から 8 Tier へ、DeepSeek の3バリアントが割り込む； ③スケジューリングの価値が圧縮される：T=1600 の週間コスト振幅は 1.67× から 1.11× へ縮小 —— キャッシュ 95% のもとでは、ピーク回避でさらに ~10% 節約できる程度なので、 正しい順序は先にプレフィックスキャッシュを直し、それからスケジューリングを語るです。 また、「出力比率」スライダーはキャッシュオンで無関係から2番目に敏感なパラメータへ変わります：同じ 95% ヒット率で、 DeepSeek-20261017 は w=2% で 86%、w=8%（デフォルト）で 68%、w=15% で 55%、w=25% で 40%、w=40% でわずか 25% 節約 —— 出力が長いほどキャッシュでは救えません。逆に、あるTierチャンピオンの入出力価格が両方とも2倍になった場合（T=1664 の DeepSeek-20261017 のように）、 キャッシュでは振幅を圧縮できず —— 依然 2.00× —— そのTierのレバーはスケジューリングです。
