# Arena 榜单性价比分析器

把 Arena.ai 任意榜单的 `(Score, Cost/Task)` 做成一条**成本-能力 Pareto 前沿**，回答：
> 「在我能接受的分数区间里，性价比最高的模型是哪个？再多花多少钱能升到下一档？」

答案区分两个页签：**①实惠排行榜**（默认页，直接给排行 + 答案卡：在质量门槛与日常任务画像下谁单次最便宜、差多少分、用多少 $，可切峰/谷价与开发/文生图等能力榜）与 **②阶梯·图析**（赢家卡 + 阶梯/散点/一周成本曲线 + 两张表）。能力榜覆盖 WebDev 6 个子榜 + 全模型榜 + **文生图榜（按张计价）**。

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 单文件工具，数据内嵌，**零外部依赖，可离线双击打开**；含价格时间引擎（峰谷价 / 促销到期）与一周 168 小时 `C(T)` 曲线 |
| `raw/*.md` | 从 arena.ai 公开页面抓下来的原始 markdown 表格（可追溯，是唯一事实来源） |
| `parse.py` | `raw/*.md` → `data/datasets.json` → **并自动注入回 `index.html`** |
| `data/datasets.json` | 解析后的紧凑数据集（构建中间产物） |
| `test/harness.js` | 最小 fake DOM，让应用脚本能在 node 里跑 |
| `test/cases.js` | 回归用例（跨实现交叉校验 + 价格时间引擎 + 缓存折扣 + 区间标注暴力核对 + 排行榜公式） |
| `test/build.py` | 抽取 index.html → 生成 `test/run.js`（**优先取 HTTP 上正在服务的那一份**） |

## 用法

```bash
# 起服务（绑定 0.0.0.0，预览环境要求）
python3 -m http.server 8080 --bind 0.0.0.0

# 改了 raw/ 之后：一条命令重新解析 + 注入 index.html
python3 parse.py

# 回归测试（测的是服务器上真正在发的那份 HTML）
python3 test/build.py && node --max-old-space-size=4096 test/run.js
```

`index.html` 是自包含的，也可以直接双击离线打开；只是那样 `test/build.py` 会退回读本地文件。

## 核心算法

```
C(T) = min { cost(m) : score(m) ≥ T }        # 门槛 T 下的最低成本
```

按分数从高到低扫，只有当某模型比「已见过的所有更强模型」都便宜时，它才成为一档。
得到的序列就是 Pareto 前沿，`C(T)` 关于 T **单调不减** —— 这就是「每个阶段都有一个性价比最高的模型」的严格版本。

每一档**真正统治**的门槛区间（推导：门槛为 T 时达标集合 = `{score ≥ T}`，赢家 = 其中成本最低者）：

- `lower` = 下一档（更弱更便宜）的分数 **+ 1** —— T 只要 ≤ 下一档分数，下一档就也达标，而它更便宜，赢家立刻换人
- `upper` = **本档自己的分数** —— T 再高本档就不达标了
- 顶档 `upper` = 数据集最高分（门槛超过它就是 `degraded`，工具仍返回顶档并给出警告）
- 底档 `lower` = **数据集最低分**（不是候选集最低分：被过滤器挡掉的模型不参与竞争，但门槛仍能拖到它们的分数上，那时赢家还是底档）

各档首尾相接、无缝无叠，完整覆盖 `[数据集最低分, 数据集最高分]`。

> **这里踩过一个 off-by-one**：早期版本写成 `lower = 下一档分数`、`upper = 上一档分数 − 1`，
> 结果是每一档的标注区间**两头各偏一位**，底档更退化成 `[1609,1608]` 这种空区间。
> 赢家答案一直是对的（`winnerPareto` 走的是另一条路径），错的只是「这档统治哪个区间」的标签 ——
> 而这个标签正是本工具的核心输出。现在有一条测试对 8 个数据集的**每一档**逐个门槛暴力核对
> 「标注区间 == 实际获胜区间」（25971 次判定），逐位相同才算过。

### 严格 CI 模式

若「更强的一档」与「更便宜的一档」在 95% 置信区间上不可区分
（即 `A.score − A.ci_down ≤ B.score + B.ci_up`），就不该为这份统计噪声多付钱 →
合并两档，保留更便宜的那个作为该段代表。实测：

| 数据集 | 模型 / 有成本 | 点估计 | 严格 CI |
|---|---|---|---|
| WebDev · Overall（开源） | 63 / 47 | 8 档 | 8 档（头部 CI 很窄，合并不动） |
| WebDev · Frontend（开源） | 63 / 47 | 8 档 | **7 档** |
| WebDev · React（开源） | 59 / 47 | 8 档 | — |
| WebDev · Fullstack（开源） | 35 / 34 | 6 档 | **4 档**（票数少、CI 宽） |
| Image-to-WebDev（开源） | 17 / 15 | 2 档 | — |
| WebDev · Overall（全部模型） | 40 / 39 | 9 档 | **6 档** |
| Text-to-Image（全部模型） | 87 / 61 | 8 档 | — |

（2026-11-21 榜面；「—」= 该榜本轮未跑 strict 对照，测试只覆盖 4 个代表榜。）

## 测试

`test/build.py` 把 **HTTP 上正在服务的那份 `index.html`** 抽出应用脚本，与 `test/harness.js`（最小 fake DOM）、
`test/cases.js`（64 条用例）拼成 `test/run.js`，再用 node 跑。关键断言：

- 前沿成本随分数严格递增；前沿上没有任何成员被其它模型支配
- 各档门槛区间无缝无叠、完整覆盖分数域
- **暴力校验**：对每个整数门槛 T，工具给出的赢家 == `min{cost | score ≥ T}` 的暴力解
  —— 8 个数据集共 3347 个门槛，0 偏差（491 + 511 + 272 + 555 + 518 + 252 + 215 + 533）
- 拖动分数线时赢家的出现顺序 == 前沿顺序
- 3 种口径 × 2 种 CI 模式 × 6 个门槛下渲染不抛异常
- 粘贴解析器：有/无 `Overall Rank` 列、制表符分隔、Preliminary/AutoEval 标记、Rank Spread 不被误读成票数、
  **模型名内嵌 `[..]`**（如 `FLUX.2 [max]`）不被切断
- **无成本列的榜单**（arena.ai 的 WebDev · HTML 子榜整列 Cost/Task 为空）：不崩溃，且明确告知原因
- **交叉校验**：浏览器版 `parsePasted()` 解析 `raw/*.md` 的结果，与 `parse.py` 写出的 `datasets.json`
  逐字段比对 —— 8 个数据集 / 427 行 × 16 字段 = **6832 个单元格，0 处差异**。两套独立实现互为参照。
- **价格时间引擎**（16 条）：全关时 63 个模型的成本必须逐个等于 `cRaw`（无损）；峰时 DeepSeek 谷价模型 ×2、
  峰价模型不动；谷时反之；周六 02:00 仍按谷价（峰时窗口只在工作日）；GLM 促销在 09-08/09-09 两侧取值正确、
  倍率 2.9452；输出占比滑块只影响「输入输出涨幅不同」的修正；存疑规则默认关闭；
  **峰时下 491 个门槛仍与暴力解逐个一致**（说明价格被改写后阶梯结构没坏）；
  `weekCurve` 168 点、峰时小时数恰为 35、成本只在时段边界跳变；`idxOf/dowHourOf` 168 个索引往返一致；
  `weekSpan` 波动区间；比值口径的 `ratio` 必须用修正后的成本重算；32 种（时刻 × 门槛 × 数据集）组合渲染不抛异常。
- **区间标注暴力核对**：对 8 个数据集的每一档，逐个整数门槛判定「实际获胜区间」，
  与标注区间逐位比对 —— 0 处偏差，且每档统治区都连续。
- **实惠排行榜**（5 条）：画像成本公式与手算逐位对照（写入倍率 1.25× + 缓存 95% + 峰谷修正，
  DeepSeek 谷/峰画像成本恰 ×0.5）；达标过滤 + 成本升序 + 冠军 == 达标集暴力最小成本；
  门槛 99999 被钳制到 score_max（只剩顶档达标）；文生图榜按张计价（画像区隐藏、成本直用实测）；
  页签状态机 + deep 重渲烟雾。
- **缓存折扣**（11 条）：引擎结果与**独立手算公式**逐项吻合（含 Anthropic/OpenAI 的 1.25× 写入倍率）；
  命中率 0→100% 成本单调不增、且 `h=0` 与「关闭缓存」逐位相同；`h=100%` 时不低于「读取价 + 输出」地板；
  缓存读取价随峰谷/促销**自动缩放**（DeepSeek 峰 $0.006 / 谷 $0.003，GLM 促销期 $0.01 / 促销后 $0.03）；
  三档来源（公布价 / 一律 10% / 关闭）互斥且可还原；缓存 95% + 峰时下 495 个门槛仍与暴力解一致；
  全门槛对照 `h=0` vs `h=95%`（491 个门槛中 173 个换冠军）；Gemini 12-01 未来事件；
  **面板与 README 引用的百分比被钉成断言**（w=2/8/15/25/40% → 省 86/68/55/40/25%）；93 种渲染组合不抛异常。

## 价格口径：这是谁的价格？

**结论：`Price $/M` 是各厂商第一方 API 的公开标价，`Cost/Task` = 实测 token 用量 × 该标价。
既不是 Arena 自定的统一价，也不是自建硬件的摊销成本。**

### 证据一：与独立定价索引逐条对上

对照 [benchr.org/pricing](https://benchr.org/pricing)（2026-09-11 快照，标注"无付费位"）：

| 模型 | Arena `Price $/M` | benchr（厂商官方） | |
|---|---|---|---|
| Kimi K3.1 Pro / Kimi K3 | $2/$10 · $3/$15 | Moonshot $2.00/$10.00 · $3.00/$15.00 | ✓ |
| GLM-5.2 / GLM-5.3 | $1.40/$4.40 | Z.AI $1.40/$4.40 | ✓ |
| Claude Opus 5.5 / Sonnet 5.5 / Haiku 5.5 | $4/$20 · $2/$10 · $0.10/$0.50 | Anthropic 同 | ✓ |
| GPT-6.1 Sol / Terra / GPT-6 Astra | $2/$10 · $1/$5 · $10/$50 | OpenAI 同 | ✓ |
| Grok 4.7 · Gemini 4 Argon | $2/$6 · $2/$10 | xAI / Google 同 | ✓ |
| Mistral Large 4 · MiniMax M3 · DeepSeek V4-Pro | $0.70/$2.10 · $0.30/$1.20 · $1.32/$3.96 | 同 | ✓ |

**开源模型标的也是 API 价**：Gemma 4 31B $0.16/$0.47（Google AI Studio）、Granite 4.1 8B $0.05/$0.10（IBM）、
Hy3 $0.13/$0.53（腾讯）、Qwen3.8-27B $0.40/$3（阿里）、MiMo-V2.6-Flash $0.14/$0.28（小米）——
榜单里每个模型的链接本身就指向这些平台的 API 文档。权重开放 ≠ 推理免费；
自托管的成本结构是 GPU 摊销 + 电费 + 运维，与 per-token 标价没有对应关系。

> **11-20 榜口径漂移补注**（2026-11-22 核对）：11-20 榜刷新后，8 个榜面价变动的模型里有 6 个
> 与厂商官方现价不符、而与 OpenRouter 聚合渠道价完全一致（Qwen3.5-397B / Kimi K2.7 Code /
> MiMo-V2.5-Pro / Hy3 preview / GLM-4.7 / GLM-5.3-Flash）——arena 的价格源对这部分模型
> 切到了渠道口径，厂商（阿里 / Moonshot / 小米 / 腾讯 / Z.ai）均未宣布调价。已按
> conf:'suspected' 登记 6 个事件（默认关闭，供敏感性分析）；Hy3 正式版（= 腾讯官方 ¥1/¥4
> 折算）与 Beam 1.0（厂商无公开价目表）核实后不登记。逐模型证据见 `03-pricing.js` 事件区注释。

### 证据二：Cost/Task 是实测用量，不是拍的

- 同一模型的 `Price $/M` 在本工具全部 **7 个 token 计价榜单里完全一致** → 单价是模型级常量（第 8 个文生图榜按张计价，Price 列为空）。
- 同一模型的 `Cost/Task` 在 WebDev 五个子榜（Overall / Frontend / React / 参考图还原 / Fullstack）**完全相同**，
  但 Image-to-WebDev 上不同（DeepSeek-V4.1-Flash-20261017：$0.12 vs $0.10；Kimi K3 (Max)：$1.74 vs $1.70；
  GLM-5.3-Flash：$0.15 vs $0.18）→ 用量按**任务大类**统计，不是按子榜。
- Agent 榜同时给出 `Output Tokens/Task (P50)`，可反推输入量：14 个模型反推出 **125K–1.27M 输入 token**，
  输入/输出比 **3.8–17.9×**，正是多轮工具调用的负载特征。
- `(Max)/(High)/(xHigh)` 档位**单价相同**，Cost 差 2–4 倍（Claude Opus 5.5：$5.66 vs $2.13，都是 $4/$20）
  → 差价全部来自 token 用量，不是价格歧视。

### 三个会让结论偏乐观的坑

1. **DeepSeek 峰谷定价**：榜上 20261017 版用**谷时价** $0.15/$0.60，20260910 版用**峰时价** $0.30/$1.20。
   峰时 = 工作日 01:00–04:00 与 06:00–10:00 UTC，其余时段半价。业务若不能调度到谷时，
   20261017 的 $0.12/task 翻倍到约 $0.24：它仍稳坐 1664 分那一档（7 档结构不变），
   但「1638→1664」边际单价 $0.0027 → $0.0073/分，「1664→1687」反而 $0.0343 → $0.0291/分，
   拐点跳跃从 12.8× 缩到 4.0×。
2. **GLM-5.3-Flash 用的是已过期的首发促销价** $0.05/$0.18；促销 2026-09-09 结束，现价 $0.15/$0.50（3 倍），
   其 $0.15/task 实际应约 $0.45。它本来不在前沿上，但同类促销价会让别的模型虚高。
3. **不含缓存折扣**：DeepSeek 缓存命中输入 $0.006（峰）/ $0.003（谷），Anthropic 缓存输入 $0.10–$1.00。
   多轮 agent 场景缓存命中率高，真实账单可能明显低于「标价 × token」。

### 想换成自己的口径

用工具里的粘贴框，把 `Cost/Task` 列换成你实测的账单或自托管摊销成本即可 ——
解析器只按**列名**取数，不关心数字怎么来的。这样算出的前沿就是**你的**性价比前沿。

## 实惠排行榜（页签①）

「阶梯·图析」回答的是「每个门槛区间的赢家」；**实惠排行榜**回答的是更直接的一问：
> 「在分数 ≥ T 的标准下 + 我的日常任务画像下，谁单次最便宜？比 #1 贵多少倍、强多少分、一个月用多少 $？」

- **质量门槛 T**（默认榜内 70% 位置，可拖）：达标 = score ≥ T；冠军 = 达标集里单次成本最低者（与阶梯逻辑同源：`C(T) = min{cost : score ≥ T}` 的展开视图）。
- **日常任务画像**：`单次成本 = in k × 输入价(缓存修正后) + out k × 输出价`，单价取当前情景修正后的标价（峰谷 / 促销 / 缓存折扣与左栏完全联动）。预设三档：轻量问答（2k/0.5k）、日常开发（20k/2k）、重度 agent（120k/12k），也可手填；「榜单实测」档直接用 Arena 实测 Cost/Task。
- **峰谷快捷**：此刻 / 峰时 / 谷时 三按钮，写的是同一份 `S.hour/S.dow` 状态（左栏价格情景同步）。
- **月费外推**：`单次成本 × 每天 N 次 × 30`，N 可调。
- **文生图榜按张计价**：图像模型没有可用的 token 标价口径，排行榜一律用 Arena 实测的每张图成本中位数，画像控件自动隐藏。
- 每行可点：把质量门槛移到该模型，与阶梯/散点联动。

## 时间变量：价格随时刻演变

榜面的 `Price $/M` 只是**抓取那一刻的标价**。本版把「时刻」做成一等变量，于是性价比成了一个随时间演变的量。

### 规则表 `PRICE_EVENTS`

| 规则 | 类型 | 置信度 | 默认 | 命中 |
|---|---|---|---|---|
| DeepSeek 峰谷定价 | 日内（工作日 01–04、06–10 UTC 为峰） | 已核实（官方页 + 4 家独立来源） | **开** | 5 个条目 |
| GLM-5.3-Flash 促销已结束 | 日历（2026-09-09 分界） | 已核实（benchr.org/pricing） | **开** | 1 个条目 |
| DeepSeek V4-Flash 是否也分峰谷 | 日内 | 存疑（V4-Flash 已退役，无公开确认） | 关 | 2 个条目 |
| 与第三方索引差 2× 但无促销说明 | 日历 | 存疑（Mistral Medium 3.5、GPT-6 Sol） | 关 | 2 个条目 |

规则表就在源码里，结构是「模型名 → 两个时刻的单价」，可自行增删。

### 换算公式

`Cost/Task = token 用量 × 单价`，用量不随价格变，所以

```
scale = [pin'·(1−w) + pout'·w] ÷ [pin·(1−w) + pout·w]        Cost' = cRaw × scale
```

`w` = 输出 token 占比，默认 **8%**（= 输入:输出 11:1，取自 Agent 榜 14 个模型反推的中位比；实测范围 3.8–17.9×）。
DeepSeek 峰谷是输入输出**同比**涨跌，`scale` 恒为 2 或 0.5，与 `w` 无关；`w` 只影响 GLM 那种输入 ×3、输出 ×2.8 的修正。

### 结论真的会变（`overall_os`；示例基于 2026-11-14 首抓快照 Score 1193–1687，最新数字以工具实时计算为准）

| 情景 | 前沿 | 1664 档 | 1600 档 | 1500 档 | 1438 档 |
|---|---|---|---|---|---|
| 榜面快照（全关） | 7 档 | DeepSeek-20261017 $0.12 | MiMo-V2.6-Flash $0.05 | Hy3 $0.04 | MiMo-V2.5 $0.03 |
| 周三 02:00 **峰时** | 7 档 | 同上 **$0.24** | MiMo-V2.6-Flash $0.05 | Hy3 $0.04 | MiMo-V2.5 $0.03 |
| 周三 12:00 / 周六 **谷时** | 7 档 | 同上 $0.12 | **DeepSeek-20260910 $0.03** | **DeepSeek-20260910 $0.03** | **DeepSeek-V4-Pro $0.025** |

7 个数据集里 5 个是同样的替换；`img2webdev_os` 谷时前沿从 2 档塌成 **1 档**；`overall_all` 谷时 `Muse Ember (Max)` 掉出、DeepSeek-20260910 进入。

| 升档 | 榜面 / 谷时 | 峰时 |

### 一周 168 小时曲线（图 ③）

### 三个局限

1. **分数不随时间变**：Arena Score 是 2026-11-21 的快照，所以时间轴只反映**价格**的时间性，不反映**能力**的时间性。
2. **缓存折扣已实现，但命中率是假设值**：见下一节。真实命中率取决于前缀是否稳定、TTL 是否过期、
   以及是否需要显式创建缓存（Google 的隐式缓存不保证命中，且不支持 `cachedContents`）。
3. **GLM 修正不改变任何前沿**：修正后 $0.44，在 `overall_os` 按成本排 40/44，本来就不在前沿（榜面 $0.15 时也已被 MiMo-V2.6-Flash 1638/$0.05 支配）。
   它是**口径正确性**修正，不是决策修正 —— 但这恰恰说明：榜面上可能还有别的模型带着过期的促销价，而你看不出来。

## 缓存命中率：影响最大的一个变量

Arena 的 `Cost/Task` 是按**未命中价（cache-miss）**算的 —— Agent 榜能反推出 `$4/$20` 这类原价就是证据。
所以对「前缀会被反复重读」的 agent 负载，榜面成本是**系统性高估**的。工具默认按 **95% 命中率**修正，可 0–100% 任意调，也可精确输入。

### 公式

缓存只打折**输入** token（输出永远按原价）：

```
有效输入价 = (1−h)·输入价·写入倍率 + h·输入价·缓存比例
scale     = blend(有效输入价, 输出价) ÷ blend(榜面输入价, 榜面输出价)
```

两个容易漏的设计点：

1. **存的是「缓存价 ÷ 输入价」的比例，不是绝对值。** 于是峰谷价、促销到期、未来涨价都会自动带着缓存价一起变：
   DeepSeek 峰时缓存价 $0.006、谷时自动就是 $0.003；GLM-5.3-Flash 促销期 $0.01、促销后自动 $0.03。
2. **写入倍率 `wm`。** Anthropic（5 分钟档）与 OpenAI（30 分钟档）的缓存写入**单独计费** = 输入价的 **1.25×**，
   未命中的那部分要按写入价付，所以同样 95% 命中率，Claude 的折扣比 DeepSeek 薄。
   DeepSeek / Z.ai / 小米 / 腾讯 / Google（隐式缓存）/ xAI 不单独收写入费 → `wm = 1.0`。共 14 个模型适用 1.25×。

### 三个二阶结论

1. **缓存把「排程套利」的空间压掉了。** T=1600 的一周成本振幅从 **1.45× 缩到 1.00×** —— 缓存做到 95% 之后，
   再靠躲峰时只能省 10%。正确顺序是**先把前缀缓存做上去，再谈排程**。
   但反过来：如果某档冠军的输入输出价**整体**翻倍（T=1664 的 DS-20261017 峰谷都是 2×），缓存压不动振幅，仍是 **2.00×** —— 那一档该做的就是排程。
2. **`h=100%` 也压不到零，地板由输出价决定。** 残余账单里输出 token 占 **59.7%（Hy3）～95.7%（MiMo-V2.5-Pro）**。
   所以命中率拉满之后，模型之间比的其实是**输出单价**，不是输入单价。
3. **输出占比 `w` 从无关紧要变成第二敏感参数。** 同样 95% 命中率，DS-20261017 在 w=2% 省 86%、w=8%（默认）省 68%、
   w=15% 省 55%、w=25% 省 40%、w=40% 只省 25%。负载输出越长，缓存能救回来的越少。

### 两个抓不到 / 不适用的榜单

- **WebDev · HTML 子榜**：页面结构相同，但 **`Cost/Task (P50)` 整列为空** —— 没有成本就无法算性价比，
  故未入库。工具对这种情况有明确提示（见测试用例「无成本列的榜单」），你把它的表格粘进去也不会得到空白页。
- **Agent Arena**（`arena.ai/leaderboard/agent`）：**另一套指标体系**，没有 Arena Score，
  取而代之的是 `Net Improvement %`、`Confirmed Success %`、`Praise vs Complaint %`、`Steerability`、
  `Bash Reliability`、`Tool Hallucination %`、`Sessions`、`Time/Task (P50)`、`Output Tokens/Task (P50)`。
  它同样有 `Cost/Task (P50)` 和 `Price $/M`，所以**门槛制的方法论完全适用**，
  但需要先决定用哪个百分比指标当"分数"，且百分比没有 BT 分数那个 ~1200 的偏移量
  （口径②③在那里反而不会退化）。要支持它得给工具加一套列映射，不是改数据就能用。

arena.ai **没有公开 JSON API**（`/api/*` 返回 403 Cloudflare 挑战），所以只能抓公开页面并本地留存快照。

## 方法论要点（详见工具内的「方法论」折叠面板）

1. 「cost/task 倒序 + 拖动区间左边界」本身不产生结论，真正的操作是固定门槛 T 求 `min cost`。
2. 「性价比」有三种定义，答案不同：**门槛制**（可决策）／分数-美元（退化，总选最便宜的）／超额分-美元。
3. 五个坑：CI 重叠、Preliminary 低票数、Cost/Task 是任务混合的 P50（不含长尾/延迟/重试）、数据集截断、时点性。
4. 前沿上的模型**互不支配**，不存在「前沿上哪个最好」——正确的提问是「边际交换率 $/分 从哪一档开始不划算」。
5. **价格是时间的函数**：榜面 `Price $/M` 是抓取那一刻的标价。加入峰谷价与促销到期后，
   同一门槛下的冠军和边际单价都会随时刻变。工具默认显示「此刻」，
   一键切回「榜面原样（全关）」即可复现只按榜面价算出的那套结论。
6. **缓存命中率是影响最大的变量**（默认 95%）：榜面成本按未命中价算，对 agent 负载系统性高估。
   开缓存后头部模型省 59–79%、排程套利空间 1.45×→1.00×，
   而 `h=100%` 的地板由**输出单价**决定 —— 详见「缓存命中率」一节。
